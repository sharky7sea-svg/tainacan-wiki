# 最適化

## Tainacanを最適化するためのガイド

このページでは、Tainacanのパフォーマンスを最適化するためのサーバー向けのヒントと設定ガイドラインをまとめています。

ここに記載されている内容の一部はWordPress管理画面から直接実行できますが、その他の内容では、いくつかの設定ファイルを編集し、サーバー設定にアクセスする必要があります。サーバー管理に関する知識が必要になる場合もあります。


------

## システムチェック

Taincanには、インストールに関する重要な情報を提供する**システムチェック (System Check)**ページがあります。

1. WordPress管理画面にアクセスします。
2. 左側のメニューでTainacanにマウスを合わせます。
3. サブ項目の**システムチェック (System Check)**を選択します。

この画面には次の情報が表示されます。

* **WordPressバージョン**：現在のWordPressバージョンを最新バージョンと比較して表示します。
* **PHPバージョン**：サーバーにインストールされているPHPのバージョンを表示します。
* **データベースバージョン**：サーバーにインストールされているデータベースサーバーのバージョンを表示します。
* **PHPモジュール**：サーバーにインストールされている、必須および推奨PHPモジュールに関する情報を表示します。
* **PHPスクリプトの最大実行時間 (Maximum exection time of PHP scripts)**：PHPスクリプトの最大実行時間の現在の値を表示します。
* **パーマリンク構造**：パーマリンク構造が正しく設定されているかどうかを表示します。
* **アップロードフォルダー**：アップロードフォルダーへの書き込み権限が正しく設定されているかどうかを表示します。
* **アップロード上限**：サーバーの設定に基づいて、ユーザーがアップロードできる最大ファイルサイズを表示します。
* **Cron**：Cronジョブの設定に関する情報を表示します。

結果の左側には、次を示す小さなアイコン（▇）が表示されます。

* <span style="color: #a23939">▇</span> - 設定が正しくありません。Tainacanが動作しない可能性があります。
* <span style="color: #e69810">▇</span> - 設定は部分的に正しい状態です。一部の機能が動作しない可能性があります。
* <span style="color: #25a189">▇</span> - 正しい設定です！


### Imagickモジュールの権限（PDFファイルのサムネイルが生成されない問題を解決する）

Imagickモジュールは、PDFファイルから最初のページを抽出し、アイテムのサムネイルを自動的に生成するために使用されます。このモジュールがない場合、システムチェックで警告が表示されます。

ただし、Imagickパッケージの最近の変更により、PDFファイルを開いて読み取る権限がない状態で事前設定されている場合があります。

これを解決するには、次の操作を行う必要があります。

`/etc/ImageMagick-6/policy.xml`（または`/etc/ImageMagick/policy.xml`）で、次の行を探します。

```
<policy domain="coder" rights="none" pattern="PDF" />
```

そして、ImageMagickのPDFコーダーによる読み取りと書き込みを許可するように変更します。

```
<policy domain="coder" rights="read|write" pattern="PDF" />
```

最後に、Webサーバーを再起動することを忘れないでください。

## パフォーマンスに関するガイド

### 一覧にデフォルトで表示するメタデータの数を減らす

アイテム一覧の表示が遅い場合、特に「テーブル」表示では、一覧にデフォルトで表示するメタデータの数を減らしてください。一覧に表示するメタデータが少ないほど、表示は速くなります。

これを行うには、コレクションのメタデータ設定ページにアクセスし、メタデータを編集して、「一覧に表示」(Exibir na listagem)オプションを探し、「デフォルトでは表示しない」(não exibir por padrão)を選択します。このオプションを設定しても、ユーザーは必要に応じて一覧にこのメタデータを表示できますが、デフォルトの一覧からは削除されるため、訪問者の読み込みが速くなります。

### 一覧に表示するアイテムの最大数を制限する

デフォルトでは、Tainacanは一覧またはAPIへのリクエストで、1ページあたり96アイテムという上限を設定しています。いくつかテストを行い、この数がサーバーに適しているか確認してください。

この数が大きすぎてリクエストが非常に遅い場合は、適切な使用感を確保するために減らすことができます。

同様に、サーバーの性能が高い場合は、この数を増やしてより完全な一覧を提供できます。これは、CSVなど別の形式でコレクションにアクセスする訪問者向けに生成されるリンクで特に役立ちます。1ページあたりのアイテム数が多いほど、コレクションのすべてのアイテムを取得するためにアクセスするページ数は少なくなります。

この設定を変更するには、`wp-config.php`ファイルに次の行を追加します。

```php
define('TAINACAN_API_MAX_ITEMS_PER_PAGE', 96);
```

`96`を任意の数に置き換えてください。

### テキスト検索の速度を向上させる

小規模なコレクションでは、Tainacanのデフォルト設定で問題なく動作し、キーワードによる一般検索も効率的に行えるはずです。しかし、やや大規模なコレクションでは、アイテムのすべてのメタデータから語句を探すこの検索は、かなり非効率になることがあります。

このボトルネックには、理想的な解決策と暫定的な解決策があります。

理想的な解決策は、WordPressをElastic Searchという検索サーバーと統合することです。Elastic Searchのインストールと設定は、少なくとも現時点ではこのドキュメントの対象外です。しかし、そのようなサーバーを稼働させたら、ElasticPressプラグインをインストールするだけです。（この統合はまだ実験段階ですが、非常に良い結果が出ています。さらに成熟したら、専用のドキュメントを作成します。それまでの間、試した結果をぜひお知らせください。）

暫定的な解決策は、検索をWordPressの標準的な動作に限定することです。WordPressの標準検索では、アイテムのタイトルと説明だけを検索します。検索範囲ははるかに狭くなりますが、速度は大幅に向上します。

これを行うには、`wp-config.php`ファイルに次の行を追加します。

```php
define('TAINACAN_DISABLE_DEFAULT_SEARCH_ENGINE', true);
```

詳しくは、開発者向けドキュメントの[検索エンジン](/dev/search-engine)を参照してください。

### ファセットを調整する

デフォルトでは、ファセットに読み込まれる値は、現在行っている検索を常に考慮します。つまり、フィルターを選択するとファセットが再読み込みされ、結果にアイテムを表示できる値だけが表示されます。このように、ユーザーがフィルターを追加するにつれてファセットの選択肢が減少し、検索の「漏斗」が形成されます。

この動作が適切でない場合は、現在の検索を考慮せず、ファセットで可能なすべての値を常に表示するようにTainacanを設定できます。（場合によっては、これによってパフォーマンスが向上することもあります。）

これを行うには、`wp-config.php`ファイルに次の行を追加します。

```php
define('TAINACAN_FACETS_DISABLE_FILTER_ITEMS', true); 
```

### ファセットの読み込み速度を向上させる

コレクションの規模やサーバーの性能によっては、ファセットやフィルターの数が多いこともサイトの使用感を悪化させる可能性があります。

ファセットの読み込みが遅い場合、最も適切なのは、このページの「サーバー設定の調整」セクションのガイドラインを確認することです。

サーバー設定を変更するアクセス権や条件がない場合は、次の方法があります。

1. ファセットの数を減らし、不可欠なものだけを残すことを検討してください。管理作業には不可欠でも、一般の訪問者のナビゲーションには不要なファセットがある場合は、「編集者にのみ表示」を設定してください。これにより、訪問者の使用感を向上させることができます。
2. ファセットごとのアイテム数のカウントを無効にします。これを行うには、`wp-config.php`ファイルに次の行を追加します。
```php
define('TAINACAN_FACETS_DISABLE_COUNT_ITEMS', true);
```

ファセットについて詳しくは、開発者向けドキュメントの[ファセット検索](/dev/faceted-search)を参照してください。

## サーバー設定の調整

このセクションの調整は、Apacheサーバーの設定に関するものです。アクセス方法や設定方法は、使用するサーバーやホスティングサービスによって大きく異なる場合があります。ホスティングサービスによっては、これらのオプションのすべてにアクセスできない可能性があります。

各設定を正確に行う方法については、使用するサーバーのドキュメント、担当のシステム管理者、またはホスティングサービスのテクニカルサポートに相談してください。ここで推奨するディレクティブは、次の設定のサーバーを前提としています。

* プロセッサー：Intel(R) Xeon(R) CPU E5-2609 0 @ 2.40GHz、4コア。
* オペレーティングシステム：Ubuntu Linux 16.04.1。
* 物理メモリと仮想メモリ：16 GBおよび2 GB。
* カーネルとCPU：Linux 4.4.0-72-generic on x86_64
* Apacheのバージョン：2.4

### サーバーの*タイムアウト*を延長する

デフォルトでは、多くのサーバーでタイムアウトが`30秒`に設定されています。これは、完了までに30秒を超えるリクエストがキャンセルされることを意味します。

通常、この時間で十分ですが、アイテムの一部のエクスポート、インポート、一括編集など、特定の操作ではボトルネックになる場合があります。

安全のため、この値を`200`～`300秒`程度に増やしてください。

### *KeepAlive*を設定する

このディレクティブを`on`に設定すると、Apacheへの持続的な接続が許可されます。パフォーマンスを向上させるには、このオプションを`on`に設定し、1つの接続で複数のリクエストを許可することをおすすめします。

MaxKeepAliveRequests：このディレクティブは、上記のKeepAliveオプションが`on`に設定されている場合に、1つの接続で許可するリクエスト数を設定するために使用します。このオプションを`0`に設定すると、無制限であることを示します。

KeepAliveTimeout：このディレクティブは、接続を閉じる前にApacheが次のリクエストを待つ時間を秒単位で設定するために使用します。`10`は適切な平均値です。

### *MPM Prefork*を設定する

Tainacanの一部のページ、特にアイテム一覧では、サーバーに対して多数の同時リクエストが行われます。このような状況でパフォーマンスを向上させるには、ApacheサーバーのMPM Preforkモジュールを設定することをおすすめします。

以下に示す各設定ディレクティブの概念については、すべての関連事項を説明している[記事1](https://elias.praciano.com/2015/12/como-configurar-o-modulo-mpm-prefork-para-melhorar-a-performance-do-servidor-web-apache/)を読むことをおすすめします。また、環境に最適な設定を決めるには、設定値を決定するための簡潔で客観的な方法を示している[記事2](https://www.woktron.com/secure/knowledgebase/133/How-to-optimize-Apache-performance.html)を読むことをおすすめします。

以下は、`/etc/apache2/mods-availave/mpm_prefork.conf`ファイルで行うことを推奨する設定です。

* **StartServers**：値を`4`に設定します。
* **MaxClients**：値を`256`に設定します。
* **MinSpareServers**：値を`15`に設定します。
* **MaxSpareServer**：値を`30`に設定します。
* **MaxRequestsPerChild**：値を`5`に設定します。
* **MaxRequestWorkers**：値を`250`に設定します。

これらの設定を行ったら、もう1つ重要な点として、Tainacanのプラグインとテーマを実行するWordPressのインストール環境を保護する必要があります。次のセクションでは、この点について説明します。

## WordPressのセキュリティ強化

最初の手順は、インストール環境のファイルとディレクトリの権限を正しく設定することです。これは、次のコマンドで行うことができます。

ディレクトリの場合：
```terminal
find /caminho/para/a/pasta/do/wordpress/ -type d -exec chmod 755 {} \;
```

ファイルの場合：
```terminal
find /caminho/para/a/pasta/do/wordpress/ -type f -exec chmod 644 {} \;
```

スクリプトにユーザーがアクセスすべきでない場所に追加できる保護対策もあります。その方法の1つは、`mod_rewrite`を使って`.htaccess`ファイルでスクリプトをブロックすることです。

```directive
RewriteEngine On
RewriteBase /
RewriteRule ^wp-admin/includes/ - [F,L]
RewriteRule !^wp-includes/ - [S=3]
RewriteRule ^wp-includes/[^/]+\.php$ - [F,L]
RewriteRule ^wp-includes/js/tinymce/langs/.+\.php - [F,L]
RewriteRule ^wp-includes/theme-compat/ - [F,L]
```

`.htaccess`を使って`wp-config.php`ファイルへのアクセスをブロックすることも、興味深い対策です。WordPressのインストール環境にある`.htaccess`ファイルに次のコードを追加するだけです。

```php
<files wp-config.php>

order allow,deny

deny from all

</files>
```

アップロードディレクトリでのファイル一覧表示と、*.php*ファイルへの直接アクセスを無効にします。WordPressのインストール環境の`/wp-content/uploads`ディレクトリ内に`.htaccess`ファイルを作成し、次の内容を記述します。

```php
Options -Indexes

<Files *.php>

Require all denied

</Files>
```

### Wordfence

セキュリティに関する推奨事項の最後として、[Wordfence](https://wordpress.org/plugins/wordfence/)プラグインをインストール、有効化、設定することをおすすめします。このプラグインには、WordPressのインストール環境をさまざまな攻撃や脆弱性の悪用から保護するための多くの機能があります。

プラグインとそのドキュメントには[こちら](https://wordpress.org/plugins/wordfence/)からアクセスできます。

## キャッシュ

サイトにキャッシュを追加するWordPressプラグインは数多くあります。これは良い方法であり、訪問者のページ読み込み時間を短縮できます。

ただし、Tainacanサイトでキャッシュを設定する際には注意すべき点があります。

Tainacanは`nonces`を使用しています。これは、ユーザーが特定の操作を実行する意図を確認するためのセキュリティ手順です。`nonces`はユーザー向けに生成されるコードで、短い期間だけ有効になり、その後再生成されます。

キャッシュプラグインを正常に動作させるには、**キャッシュの有効期間を12時間以内に設定する必要があります**。これは`nonce`コードの有効期間です。キャッシュの有効期間がこれより長いと、ユーザーが期限切れのコードでWebサイトにアクセスし、権限の問題が発生する可能性があります。

この問題について詳しく理解したい場合は、[こちらの記事](https://medium.com/myatus/wordpress-caching-and-nonce-lifespan-bb357d984da9)と[こちらの記事](https://joshpress.net/wordpress-nonces-and-wordpress-caching/)を確認してください。
